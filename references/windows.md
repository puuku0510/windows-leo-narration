# Windows 実行メモ

このメモは、購入者の手元にあるハーネスを Codex から動かす際の確認事項。作者が Windows での動作を保証しているという意味ではない。コマンドやファイル構成が違う版では、購入した版の表示と説明を優先する。

## 環境

- Git Bash で `bash`、`curl`、`python3`、`ffmpeg` の実行可否を確認する。`python3` が見つからない Windows 環境では Python の実体を調べ、個人の実行環境でのみ `python3` という呼び出しに対応させる。
- 日本語を含む JSON は UTF-8 で保存する。PowerShell から Python を起動する場合は `PYTHONUTF8=1` をそのプロセスへ設定する。コンソール表示の文字化けと、実際に API へ送ったデータの破損は分けて調べる。
- ハーネスを個人用の場所へ展開し、Git Bash から `bash install.sh --check` を実行する。結果を見て不足分を整え、本人の同意のあるインストール先へ `bash install.sh --codex` を実行する。既存の同名スキルがあれば上書き前に差分を確認する。
- `XAI_API_KEY` と、購入版の Gemini 聴き取りに使う `GEMINI_API_KEY` は利用者本人が設定する。実行時に存在するかだけを確認し、値は表示しない。Windows の環境変数を恒久保存する必要はない。評価スキルと `pyopenjtalk` も作動するか確認する。

## まず短い音声で動作確認

購入版のヘルプで Leo の音声名と入力 JSON の形式を調べ、個人の作業フォルダーに短い日本語原稿を作る。ハーネスの `tts.sh` をそのフォルダーへ向けて実行し、MP3 が作成され、最後まで再生できることを確認する。外部 API 呼び出しとその料金は利用者のアカウントに発生する。

Git Bash の `curl` が日本語 JSON を正しく送れず、API が `invalid escape` 等を返す場合は、リクエストとレスポンスを再確認する。**購入した個人用コピーの中だけ**で UTF-8 を保つ呼び出しへ修正するか、作者の Windows 対応版を確認する。修正済みハーネスをこのスキルへ入れたり、第三者へ渡したりしない。原因を確かめずに本編を再試行せず、別の TTS へ自動で切り替えない。
